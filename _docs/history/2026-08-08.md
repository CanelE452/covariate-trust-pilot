### 발견 2 — 합성 rho_I 와의 대응이 통계량 선택에 따라 뒤집힌다 (가장 중요)

H1 의 x 는 `|lag-1 autocorr of inter-arrival gaps|` 다. 그런데 `screen.py` 는
`occurrence_binary_acf1_train`(0/1 수열의 lag-1 자기상관)도 계산해 두었고, 이쪽이
Markov occurrence 과정의 rho 에 더 직접 대응한다. 둘을 비교했다.

```

──────────────────────────────────────────────────────────────────────────────────────

m5        lumpy         -0.250                -0.2089                       [-0.3255,-0.0948]

```

두 측도는 **음의 상관**이고, M5 intermittent 에서 H1 의 부호가 +0.15 -> **−0.52 로
뒤집힌다.** 즉 "발생의 시간구조가 강할수록 Hurdle 이 유리하다"는 서술은 어느 통계량을
occurrence dependence 로 부르느냐에 전적으로 의존한다.

단, binary acf1 은 밀도(ADI)와 교란돼 있을 수 있어 −0.52 를 그대로 인과 해석하면 안
된다. 미해결 — 별도 설계 필요.

### 정정 — 합성 rho_I 정의 확정 (앞 절의 "미확인" 해소)

이 세션 초반에 "합성 코드가 이 머신에 없어 rho_I 정의를 확인 불가"로 남겼으나,
`m5dataset` 저장소를 보유한 다른 세션이 생성기를 직접 읽고 확정했다
(`dgp.py:43/80/162`, d=4·d=8 각 9셀 200계열 재생성으로 실측).

```
합성 rho   = 잠재 Markov 상태 수열의 lag-1 자기상관 (관측값 아님)
interval   gap = d + s  (상태의 결정적 2값 아핀 사상) -> 상관 불변
           => acf(gap) = rho_I           target -0.80 -> 실측 -0.8026 / -0.8064
magnitude  M = 1 + Poisson(lambda-1)     -> 수준내 잡음으로 감쇠
           => acf(M) = rho_M x 25/34 = rho_M x 0.7353   실측 비율 0.70~0.75
```

**결론: SCREEN 의 x(`rho_interval_abs_train`)는 합성 rho_I 와 정확히 같은 양이다.**
동결 기록(`prereg.py` DESCRIPTOR_RULES)의 전제가 맞았다. 따라서 앞의 "발견 2"에서
부호가 뒤집힌 `occurrence_binary_acf1`(0/1 수열 자기상관)은 **합성 knob 이 아니며**,
2단계 서사의 위협이 아니다. 다만 "occurrence dependence" 라는 말이 두 가지 다른 양을
가리킬 수 있다는 사실 자체는 남으므로 진단 항목으로 유지한다.

magnitude 는 감쇠하므로 **합성 rho_M = +0.8 은 실데이터 척도로 +0.5882** 이다.
감쇠계수 0.7353 은 `lambda_levels = (5, 15)` 에 종속된다.

## Safe-P0L1 shrinkage calibration — 하방은 지키지만 Fresh 는 회복하지 못한다

기존 `EXTERNAL_VALIDATION_NOT_REPLICATED` 와 P0L1 결과는 그대로 보존한다.
TEST 는 하나도 열지 않았고 새 dataset 도 쓰지 않았다.
새 패키지 `experiments/safe_p0l1/`, 산출물 `results/gate_safe_p0l1/` 26개.

### 방법

P0L1 을 그대로 두고 출력만 static alpha 쪽으로 당긴다.

```
g_safe = alpha + lambda * (g_raw - alpha)
```

lambda 는 **과거 fold 의 cross-fitted OOF 에서만** 닫힌형으로 푼다.
mixture MSE 가 g 에 대해 이차식이므로 fold 별 (num, den, alpha, n) 만 있으면
lambda 는 해석적으로 나온다.

```
lambda = sum_f d_f (num_f - alpha_f den_f)/n_f  /  sum_f d_f^2 den_f/n_f     (d_f = g_raw - alpha_f)
lambda <- clip(lambda, 0, 1)
```

첫 fold 는 과거가 없으므로 `lambda = 0` (COLD_START) — 그 fold 는 static alpha 그대로다.
denominator 가 1e-8 이하면 `SAFE_GATE_NO_CALIBRATION_SIGNAL` 로 역시 0.
fold 경계·expert·feature·architecture·loss 는 P0L1 에서 그대로 가져왔고 아무것도 탐색하지 않았다.

### identity test

lambda=0 이면 g_safe 가 alpha 와, lambda=1 이면 g_raw 와 같아야 한다.
`atol=0` 으로 시작했다가 lambda=1 에서 실패했는데, 실제 오차가 1.11e-16 (float64 eps 미만)이라
부동소수점 결합순서 문제였다. tolerance 1e-12 로 고쳐 16/16 통과.
anchor 가 `alpha_safe = clip(alpha, 1e-4, 1-1e-4)` 를 쓰므로 비교 대상도 raw alpha 가 아니라
alpha_safe 로 맞췄다 (alpha=0 fold 에서 처음 실패한 원인).

## Routing information ceiling — 더 강한 learner를 줘도 같은 feature로는 일반화하지 못한다

기존 결과는 전부 보존한다: Gate-v2 `EXTERNAL_VALIDATION_NOT_REPLICATED`,
Gate-v3 `DIRECT_LOSS_SUPPORTED` / `ALPHA_ANCHOR_SUPPORTED=False` / `FEATURE_ROUTING_LIMITED=True`,
P0L1 `P0L1_TEMPORAL_STRONG`(해석 B), Safe-P0L1 `SAFE_P0L1_TEMPORAL_MIXED`.
TEST 미채점, 새 dataset 미사용.
새 패키지 `experiments/routing_information_ceiling/`, 산출물 `results/routing_information_ceiling/` 32개.

### 질문

P0L1 의 이득이 작고 Fresh 가 음수인 이유가

- H_CAPACITY: feature 에는 정보가 있는데 529-param MLP 가 못 뽑는 것인지
- H_INFORMATION: feature 자체에 시간적으로 안정된 routing 정보가 없는 것인지

를 가른다. **바꾸는 것은 routing function approximator 하나뿐**이고
expert / G-NOSCALE feature / fold / normalization / direct mixture loss 는 전부 P0L1 artifact 그대로다.

### direct mixture loss 를 weighted regression 으로 바꾼 것이 핵심

HGB 는 custom loss 를 못 받으므로 등가 변환을 썼다. origin 별로

```
L_j(g) = (sse_a_j - 2 g num_j + g^2 den_j)/n_j
       = C_j + (den_j/n_j) (g - u_j)^2 ,     u_j = num_j/den_j
```

이므로 **target u_j, sample_weight den_j/n_j 인 weighted squared error** 가 같은 문제다.
u 를 미리 [0,1] 로 자르지 않고 예측을 마지막에 clip 해서 constrained optimum 을 만든다.
den <= 1e-8 (기존 FLAT_THRESHOLD) 인 origin 은 target 이 식별되지 않아 fitting 에서 제외하고
evaluation 에는 그대로 둔다 — 사전 고정.

실제 OOF row 로 g = 0, .1, .25, .5, .75, .9, 1 에서 검증:
**max abs error 5.68e-14 (592,620 비교) PASS**.
g=1 에서 max rel error 가 6.3e-05 로 뜨는데 그 지점 loss 자체가 0 에 가까운 origin 때문이고
절대오차는 여전히 1e-14 다 — 그래서 절대 기준으로 판정했다.
