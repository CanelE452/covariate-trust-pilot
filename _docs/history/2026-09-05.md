**1. `tests/prob_head_structure_full_v1/test_evaluation.py`**

`test_validation_selected_p2_applies_to_distinct_sealed_outer_without_cross_split_hash_reuse`의
monkeypatch에 `p_zero` 패치를 추가했다.

- Before: `cdf`만 `1 - exp(-y)`로 패치 → pooled CDF는 `F(0)=0`인데 `p_zero`는 실제 분포값을
  유지해 **유효하지 않은 예측분포**가 생성됨. 12-case 그리드에서 `p_zero >= 0.01`인 case가
  나오면 `q_025`는 zero-mass 규칙으로 0이 되고 `q_010`은 양수라 quantile crossing 발생.
- After: 형제 테스트 `test_p2_uses_bound_native_cdfs_and_frozen_grid_tiebreak`와 동일하게
  `p_zero`를 `torch.zeros_like(self.mu)`로 함께 패치해 `F(0) == p_zero` 불변식 복원.
- 이유: 프로덕션에서 `p_zero = einsum(simplex, teacher_pzero)`이고 pooled CDF의 0 지점 값도
  같은 가중평균이므로 불변식이 구조적으로 성립한다. 즉 구현이 아니라 픽스처가 틀렸고,

## PROB-HEAD-STRUCTURE-FULL-v1 — 실행 착수 중 발견한 계약 위반 6건

실제 실행을 시도하며 드러난 문제들. 전부 **결과가 관측되기 전에** 수정했다.

```text
#   문제                                   비용     성격
──────────────────────────────────────────────────────────────────
1   미실행 A/B/C branch 에 NO_GO 라벨      3분      검증 안 한 주장
2   R1 이 층화표본 미사용                  3.5분    §13 위반
3   teacher checkpoint 미저장              2분      §47 위반, 하류 전제 결여

```

5·6번은 제가 놓친 것을 **모듈의 봉인 장치가 잡아냈다**.

### 1. 미실행 branch 를 NOT_EVALUATED 로 (`stages.py`)

`NO_GO`는 "사전등록 임계값으로 검증했으나 실패"를 뜻한다. 미배선 A/B/C에 붙이면
STATUS.md에 근거 없는 주장이 박힌다. gate 상태가 `NOT_EVALUATED`면
`NOT_EVALUATED_<GATE>_NOT_RUN`을 내고, method branch가 하나도 실행되지 않았으면
전체 추천은 `INTEGRITY_BLOCKED_NO_SCIENTIFIC_VERDICT`로 떨어진다.

### 2. 실제 데이터 stage 를 봉인 provenance 체인으로 (`stages.py`)

간이 RNG 단순무작위 표본 → 봉인 체인으로 교체:

```text
source manifest (4개 소스 해시)  aggregate 39496af3…
dataset audit                    COUNT_PRIMARY, confirmatory_eligible=True,
                                 canonical_source_attested=True, panel [29290,1941]
sample manifest                  TRAIN_ONLY_STRATIFIED_SAMPLE_MANIFEST
                                 적격 pool 29,233 → 층화표본 1,000
WindowRequest/Batch              teacher_train 228,000행 / evaluation 6,000행
```

행 단위 예측 키는 재구성하지 않고 봉인된 step 단위 `key_frame`에서 유도하며,
커버리지 불일치는 hard integrity failure.

### 3. teacher checkpoint 영속화 (`stages.py`)

S1은 셀·head당, R1은 head당 checkpoint를 저장하고 R1은 validation-split 예측까지
저장한다(pool 선택 입력). `load_teacher_checkpoint` 왕복 검증 완료.

### 4. 미배선 stage 를 미완료로 유지 (`run.py`, `stages.py`)

placeholder가 페이로드를 반환하면 완료마커가 찍혀 resume이 **영구히 건너뛴다**.
`StageNotImplemented` 예외 → `NOT_IMPLEMENTED` 기록, 마커 미생성 → 다음 실행이
새 attempt 예약하고 실제 구현 실행. 앞 stage는 resume 유지. 양방향 검증.

### 5. NB exact CDF resource guard (`stages.py`)

```text
RuntimeError: exact NB CDF summation exceeded the 200000-count resource guard
  distributions.py:236  y > 200_000 이면 거부
  _discrete_quantile    high = ceil(mean + 12*sqrt(variance) + 1) 로 bracket
```

분산이 큰 NB 적합(작은 r)에서는 bracket이 guard를 넘어 **quantile 자체를 계산할 수 없다.**
동결된 수치 한계이지 튜닝 대상이 아니다. §64대로 해당 head만
`NUMERICAL_BRANCH_BLOCKED`로 기록하고 나머지 head를 계속하게 했다. 전 head가 차단되면
예외. S2는 head가 하나라도 빠지면 3-family 정본 ladder를 거부하고 S1/S2/S3을 명시적
FAIL로 둔다 — 2-family 숫자를 3-family 라벨로 내지 않기 위해.

### 6. 완료마커 전체 바인딩 (`run.py`)

`publish_completion_marker`는 attempt 내 모든 파일 바인딩을 요구하는데 파이프라인이
`stage_payload.json`만 묶었다. S1이 parquet·checkpoint를 쓰기 시작하자 첫 마커 발행에서
즉시 실패. stage가 쓴 모든 파일을 수집해 바인딩하도록 수정.
