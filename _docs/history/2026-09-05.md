### 변경 파일

**1. `tests/prob_head_structure_full_v1/test_evaluation.py`**

`test_validation_selected_p2_applies_to_distinct_sealed_outer_without_cross_split_hash_reuse`의
monkeypatch에 `p_zero` 패치를 추가했다.

- Before: `cdf`만 `1 - exp(-y)`로 패치 → pooled CDF는 `F(0)=0`인데 `p_zero`는 실제 분포값을
  유지해 **유효하지 않은 예측분포**가 생성됨. 12-case 그리드에서 `p_zero >= 0.01`인 case가
  나오면 `q_025`는 zero-mass 규칙으로 0이 되고 `q_010`은 양수라 quantile crossing 발생.
- After: 형제 테스트 `test_p2_uses_bound_native_cdfs_and_frozen_grid_tiebreak`와 동일하게
  `p_zero`를 `torch.zeros_like(self.mu)`로 함께 패치해 `F(0) == p_zero` 불변식 복원.
- 이유: 프로덕션에서 `p_zero = einsum(simplex, teacher_pzero)`이고 pooled CDF의 0 지점 값도
  같은 가중평균이므로 불변식이 구조적으로 성립한다. 즉 구현이 아니라 픽스처가 틀렸고,
  crossing 가드는 정상 동작한 것이다. 구현은 수정하지 않았다.

**2. `experiments/prob_head_structure_full_v1/gates.py`**

`FrozenPrimaryDatasetManifest.from_selection_audit`의 `required_fields`를 producer 계약에 맞췄다.

- Before: 8개 필드 exact-set 검사
- After: `manifest_type`, `selection_manifest_sha256` 추가(10개) +
  `manifest_type == "COUNT_PRIMARY_DATASET_SELECTION_MANIFEST"` 값 검사
- 이유: `data.select_real_datasets`(06:03 수정)가 두 필드를 추가했는데 consumer인
  gates.py(05:55)가 따라가지 못해 import 자체가 실패했다. `manifest_type`은 data.py 1392/2410/2433,
  preregistration.py 1292에서 쓰이는 계통적 무결성 태그이며 `data.verify_real_dataset_selection_manifest`가
  이미 값을 강제한다. gates.py는 "pure reducer"(stdlib+numpy만 import)라 data.py를 import하지 않고
  필드 계약만 맞췄다. `selection_manifest_sha256`은 재계산 검증을 넣지 않았다 — gates.py는 이미
  audits로부터 선택 로직 전체를 재유도하므로 중복이고, 기존 변조 탐지 테스트의 기대 메시지와 충돌한다.

**3. `tests/prob_head_structure_full_v1/test_gates.py`**

`PRIMARY_THREE`를 `select_real_datasets` 경유에서 `from_audit_payload` 직접 구성으로 교체했다.

- Before: `_sealed_count_audit("auto")`, `_sealed_count_audit("carparts")`로 attested
  count-primary audit을 위조해 3-dataset 선택을 생성
- After: gates 계층 정책만 직접 검증 (`selected=("m5","auto","carparts")`)
- 이유: `implementation_plan.md` ruling 12가 "Auto/Carparts/RAF는 6개 evaluation horizon +
  warmup + validation + lookback을 공급할 수 없다"고 동결했고, data.py의
  `CANONICAL_COUNT_PRIMARY_PANEL_CONTRACTS = {m5, online_retail}` + `_verify_sealed_dataset_audit`가
  이를 강제한다. 따라서 3-dataset 선택은 데이터층에서 **구조적으로 도달 불가능**하다.
  gates.py `_validate_policy`는 최대 3개 순서 정책을 정당하게 지원하므로, 동결 계약을 위조하는
  대신 gates 계층에서 그 정책만 검증하도록 했다.
