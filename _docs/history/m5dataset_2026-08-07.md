### 발견한 충돌 3건

**1. M5 선행 zero 가 ADI 와 gap 수열을 오염 (가장 중요)**

```
선행 zero > 100일 계열      332 / 1200   (평균 210일, 최대 1716일)
ADI p90                     원본 7.99  ->  트림 후 4.91
ADI 가 0.1 이상 바뀌는 계열  346 / 1200
Favorita                    해당 없음 (최대 90일, >100 계열 0개)
```

M5 에서 상품 도입 전 구간은 **미취급**이지 zero demand 가 아니다. `prepare_m5.py` 는
원본 그대로 쓰고 `sbc_stats_for_series` 는 `ADI = len(y)/len(pos)` 로 계산하므로,
도입 전 구간이 ADI 를 부풀리고 **inter-arrival 수열 맨 앞에 거대한 가짜 gap 을 넣는다.**
그 gap 이 바로 H1 의 `rho_interval` 입력이다.

권고: train 구간 내 첫 양수 이후로 잘라서 descriptor 계산 + 학습 window 제한.
(최대 first-positive 1716 < train_end 1885 이라 전 계열이 test 구간 유지)

**2. 합성 primary metric 이 실데이터에 없음**

합성 primary loss 는 `rmse_mean_truth` — exact DP oracle 조건부 평균 대비 RMSE.
실데이터엔 oracle 이 없다. `series_metrics` 는 oracle 없이 `realized_y_mse`,
`realized_y_mae`, `occurrence_brier`, `positive_only_magnitude_mse` 를 계산 가능.

권고: SCREEN 의 delta 는 realized-y 기준. 합성 delta 와 **숫자 비교 금지, 방향만 비교**.

**3. horizon 불일치**

```
합성 study      lookback 96, horizon 24, length 576, train/val/test = 384/480/576
M5 파이프라인   horizon 28, train_cutoff = T - 2*28
```

권고: 기존 pipeline split 우선 원칙에 따라 M5-native horizon 28 + lookback 96.
Point/Hurdle 동일 적용이라 공정성 영향 없음.

### 부수 확인

- 두 데이터셋 모두 이미 정확히 1200 계열 — 추가 sampling 불필요. 단 층화 기준이
  SCREEN 지시문의 ADI quartile 이 아니라 SBC regime.
- descriptor threshold 15/20/30 어디서도 eligible 수가 거의 불변
  (M5 1200/1200, Favorita 1191~1197) -> `WARN_DESCRIPTOR_INSTABILITY` 위험 낮음.
- **G8 baseline: `2 failed, 412 passed`** — 실패 2건은 `unified_temporal_27_v3` 의
  기존 실패. 이후 `PASS_NO_NEW_FAILURES` / `WARN_EXISTING_FAILURES` 로 분리 보고.
