### [충돌] M5 availability 가드 — 마스크로 해소

`build_split` 은 평가창 안에서 availability 가 시작되면 중단한다. M5 최종 availability 는
day 1715 인데 가장 이른 fold 는 1521 에서 평가하므로 3개 fold 를 train 구간에 넣으면
반드시 걸린다. 우회 대신 **train/val 에 이미 적용되는 `_mask_before_availability` 를
OOF 블록에도 동일 적용**했다. 판매 불가 구간을 0 으로 채우는 게 아니라 손실에서 제외하고,
관측치가 하나도 없는 행은 "완벽한 예측"으로 세지 않도록 버린다.

### OOF fold 설계 (TEST 미접근)

Stage A 기하를 train 구간 안에서 반복. 각 fold 는 자기 cutoff 이후를 절대 보지 않는다.

```

Favorita  train_end 1576   folds cutoff 1240 / 1352 / 1464   origins 1268.. / 1380.. / 1492..
max_oof_target_day == train_end, strictly_inside_train = True, test_used = False
OOF rows  M5 10,776 / Favorita 10,800
```

loss 는 fold 자신의 train_scale 로 나눈 per-origin horizon MSE — 모델이 입력을 나누는
바로 그 양이라, gate 가 배우는 regret 이 큰 계열에 지배되지 않는다.
