# Table rendering specification

Four main tables. Drafts in `drafts/table{1,2,3,4}_draft.{csv,md}`, regenerated by
`render_tables.py` from verified artifacts. No number is typed in.

## Table 2 — Stage 1 factorial effects

```
draft      drafts/table2_draft.csv / .md
source     stage1_verified_contrasts.csv, model M1_HURDLE_MEAN
columns    factor or interaction | effect on G (pp) | 95% CI | reading
rows       7 contrasts, in the file's own order
precision  2 decimal places for the estimate and both interval bounds
```

`effect_pp` in the artifact **is** `G` in percentage points; this was verified by
recomputing the three main effects from the cell means, which reproduced the stored
values to three decimals. No legacy delta appears.

No significance stars: every row carries an interval, and one row
(`sparsity x magnitude`, −0.01 [−1.70, +1.69]) spans zero and is left to speak for
itself. The ZTNB variant may be added as a second column block; its signs agree on
every contrast whose interval excludes zero.

## Table 3 — core empirical validation datasets

```
draft      drafts/table3_draft.csv / .md
source     stage_a_results.json manifest; regime_h1.json for the full-pool counts
scope      M5 and Favorita ONLY
columns    dataset | series | T | train_end | test origins | lookback/horizon |
           availability | sampling
```

Footnotes carry the eligibility rule (`n_positive_train >= 20`), the freeze
timestamps (spec 18:06:38, results 18:11:16), the M5 full-pool regime counts that make
the balanced sampling visible, and one sentence stating that FreshRetailNet-LT and UCI
Online Retail II are Section 5.7 stress tests documented in the appendix.

The scope restriction is the point of this table: a reader must not be able to infer
that the stress-test datasets contributed to H1 or H2.

## Table 4 — empirical evidence summary

```
draft      drafts/table4_draft.csv / .md
source     stage_a_results.json, regime_h1.json, rule_replication/primary_result.json,
           rule_replication/secondary_overlap.json
columns    question | population | estimate | 95% CI | status | reading
rows       7: H1 on two datasets, H1 within the intermittent regime, H2 selector,
           H2 isolated mechanism, H3 on two datasets
precision  4 decimal places throughout
statuses   SUPPORTED_WITH_BOUNDARY, SUPPORTED, CONFIRMED, NOT_REPLICATED,
           CONSTRUCT_MISMATCH -- the frozen vocabulary, nothing invented
```

H2 occupies two rows on purpose: the selector row is `CONFIRMED`, the mechanism row is
`NOT_REPLICATED`, and putting them adjacent is what stops the pair being read as one
result.

**Classical baselines are not in Table 4.** Adding eight methods on two datasets to a
table that already carries seven inferential rows makes both halves unreadable. They
belong either in Table 3's section as a small separate block or in the appendix; the
recommendation is a short appendix table, with the mean-rank ordering quoted in the
Section 5.2 text where it is actually argued.
